## 音源链路的关键事实（排查结论）

- `custom-sources/*.js`（LX 脚本）**只负责取址**，协议里没有 search 动作。搜索必须由 provider 提供。
- provider 是 `builtin`（内置音源）时，搜索走 `src/extensions/builtin/search.ts` 的裸 `fetch` 直连 `music.163.com/api/cloudsearch/pc`；该接口不返回 `Access-Control-Allow-Origin`，而窗口 `webSecurity: true`，所以桌面端被 CORS 拦死 → 空列表。
- 白名单原本已覆盖 `.qq.com`、`.kugou.com`、`y.gtimg.cn`，只缺 `music.163.com`，故只加这一行。改完需重启 `npm run dev:electron`（主进程不热重载）。
- 汽水（qishui）provider 不接自定义音源：`src/extensions/customSource/index.ts` 只包了 netease/kugou/qq 三个的 `playback.getAudioSource`。所以汽水能搜但脚本不参与取址。

## 内置音源改为三平台聚合搜索

用户诉求：搜"晴天"时网易云没有周杰伦的版权版本（全是翻唱），要求搜索走全平台、播放仍走自定义音源。

- `src/extensions/builtin/search.ts` 重写：`searchNetease` / `searchQq` / `searchKugou` 三个独立函数，`searchBuiltin` 用 `Promise.allSettled` **并发**请求，结果**轮转交错**（wy[0],tx[0],kg[0],wy[1]…）后 `slice(offset, offset+limit)`。不再"网易有结果就 return"，任一平台失败只记入失败列表。
- 分页语义：每页是"合并排名的一个窗口"，各平台都取自己的前 `min(offset+limit, 100)` 条再合并。常量 `AGGREGATE_POOL_MAX = 100`，超过后 `total` 压到 `offset + songs.length` 以停止翻页（否则会无限请求空页）。
- **QQ 接口换了**：原 `c.y.qq.com/soso/fcgi-bin/client_search_cp` 现在对匿名请求返回 HTTP 500 空 body，所以从前的"QQ 兜底"从未生效过。改用 H5 的 `soso/fcgi-bin/search_for_qq_cp`（带 `g_tk/uin/platform=h5/needNewCode=1` 等参数）。字段是扁平结构（`songmid`/`albummid`/`albumname`），`fromQq` 做了新旧两种形状的兼容。
- **酷狗接口**：`https://mobiles.kugou.com/api/v3/search/song`（`mobilecdn.kugou.com` 只有 http，WebView 会当 mixed content 拦）。`fromKugou` 取 hash 的优先级 `320hash → sqhash → hash`，`nativeId` 用 `album_audio_id`，封面 `trans_param.union_cover` 模板把 `{size}` 换成 480。
- **Referer 是硬门槛**：QQ 的搜索/歌词路由只认 `Referer: https://y.qq.com/`，其他一律返回 `data.song.list: []`（实测 localhost / 无 Referer / `app://` 都是 0 条）。而浏览器 fetch 不能设 Referer。解决办法是在 `electron/main.cjs` 的 `setupCorsBypassHandlers` 里加 `webRequest.onBeforeSendHeaders`，对 `c.y.qq.com`/`u.y.qq.com`/`music.163.com`/`mobiles.kugou.com` 改写 Referer（先删掉所有大小写变体再写）。网易云其实不依赖 Referer，但它需要 `Content-Type: x-www-form-urlencoded`（fetch 可以设）。
- `src/extensions/builtin/model.ts` 加 `PLATFORM_BADGE`（网易/QQ/酷狗/酷我），`SearchResultRow.tsx` 用 `decodeBuiltinId` 在歌名后渲染平台小标签——列表里同名歌会来自多个平台，没有标签分不清。
- `test/manual/builtin_search_probe.ts`：`page.platform` → `page.platforms.join('+')`。
- 实测（搜"晴天"）：wy 336 / tx 600 / kg 480，聚合第一页第 2 条 `tx:0039MnYb0qxYhV`（周杰伦·叶惠美）、第 3 条 `kg:32100650`（周杰伦·叶惠美）。翻页无重复，`tsc --noEmit` 通过。
- 已知容量限制：QQ 与酷狗单次最多返回 30 条（`n`/`pagesize` 上限），网易可到 100，所以合并池实际约 160 条，能翻到 6~8 页。
- 取址现状（与搜索无关）：`kxh-1.7.16.js` 对 **wy** 正常；对 **kg** 用真实 320hash 能拿到可播地址（走妖狐兜底，实际是酷我 CDN 的 m4a）；对 **tx** 全通道失败（海棠 `APP_UPGRADE_REQUIRED`、ygking 域名不解析、本地 3035 拒连、cyapi/FFAPI/妖狐报 `unsupported src`）。所以 QQ 的歌能搜到但可能放不了，属脚本侧问题。

## 自定义音源脚本实测与替换（23:30–23:50）

用户反馈"网易云版权不够、想用 QQ 当主力"，于是把公开脚本全测了一遍（`shellsec/lx-music-source` 镜像 21 个脚本，逐个单目录单 host，用真实 songmid/hash 测试，并**校验返回地址**：HTTP 状态 + 文件头魔数 + 总字节数 → 折算 kbps 判断是否完整曲目）。

**结论（tx 晴天 269s，VIP 曲）**：

| 脚本 | tx | kg | wy | 判定 |
|---|---|---|---|---|
| `Hei Music聚合源.js`（59343B） | 321kbps mp3 10.3MB | 321kbps | 148kbps outer | **可用** |
| `独家音源.js` | 321kbps | 321kbps | 失败 | tx/kg 可用 |
| `念心音源.js` | 321kbps | 321kbps | 403 未授权 | tx/kg 可用 |
| `fish_music.js`（639KB） | 194kbps mp4 | 321kbps | 321kbps | 可用（tx 为 AAC） |
| `墨澜聚合音源.js` | 307kbps 但 `.mgg` 加密容器（头 `1b565617`） | 可播 | 失败 | 实际播不了 |
| `星海音乐源.js` / `星澜` | 返回地址但 HTTP 404 | 可播 | 失败 | 不可用 |
| `豆包定制 v27.4` | 全失败 | 全失败 | 全失败 | 本机 IP 全封 |
| `kxh-1.7.16` / `monster` / `sixyin` / `野花v1` | 全失败 | kxh 可 | kxh 可 | tx 已废 |

**已做的改动**：把 `Hei Music聚合源.js`（md5 `6663f253204e2222789717446e97449a`）装到 `%APPDATA%\Folia\custom-sources\`，并**改名为 `zz Hei Music聚合源.js`**。原因：`lxHost.cjs` 的 `load()` 用 `readdirSync().sort()` 决定脚本尝试顺序，第一个成功的胜出；不加前缀时 'H' < 'k'，它会抢在 kxh 前面接管 wy，把网易云降到 148kbps 的 outer 通道。加 `zz` 后顺序为 kxh → monster → sixyin → Hei → 野花，实测：wy 2.5s 走 kxh、kg 0.5s 走 kxh、tx 6.7s 走 Hei（前三个要先失败）。
- tx 的音频由 `mcp.nianxinxz.com/share/ceshi/tx.php?id=` 代理转发（公益通道，随时可能失效）。
- 若要 wx 的 tx 更快：把 monster/sixyin/野花 在 设置→自定义音源 关掉，能省约 4s。
- 用户需要手动在 设置 → 自定义音源 点「重载」或重启 App 才会加载新脚本。
- 另有备选：`fish_music.js`（tx 194k AAC，wy/kg 都是 320k），放在暂存 `.workbuddy/scratch/lx-all/`，需要时可换。
