# 2026-10-28

## folia-major：接入落雪（LX Music）自定义音源 —— 取址链路打通

**方向已定**：不做新项目、不重写。Folia 当底座，只把「播放地址」这一环交给 LX 脚本；搜索/歌单/歌词仍走 Folia 自己的 provider。原因：LX 自定义源协议里**没有 search**（搜索是 LX 内置代码），脚本只被问一个问题——这首歌的播放地址是什么，正好是 Folia 在会员/版权限制曲目上唯一缺的能力。

**新增文件**
- `custom-source/lxHost.cjs` — 脚本加载 / 元信息解析 / `vm` 沙箱 / `lx` API / 取址与多脚本回退
- `custom-source/http.cjs` — `lx.request`：主进程发请求不受 CORS、跟随 5 跳、解 gzip/deflate/br、**响应体自动 JSON.parse**
- `custom-source/mediaPolicy.cjs` — 给脚本返回的媒体地址补 `Access-Control-Allow-Origin`，否则 Web Audio 分析不出波形（可视化需要）
- `custom-source/smoke-real.cjs` — 开发用：不开 Electron 直接拿真实脚本试初始化/取址
- `custom-source/README.md` — 放置目录、协议、字段映射、实测结论

**改动文件**
- `electron/main.cjs` — 懒加载 host；`onHeadersReceived` 追加 mediaPolicy；`onBeforeRedirect` 登记重定向目标；5 个 IPC（list/reload/set-enabled/resolve-url/open-folder），均过 `isFirstPartyWindowContents`
- `electron/preload.cjs` — 暴露 `window.electron.customSource`
- `src/extensions/customSource/index.ts` — 只装饰 `netease/kugou/qq` 的 `playback.getAudioSource`，失败回落原 provider；`originals` Map + `wrapped` Set 支持反复装卸
- `src/bootstrap.tsx` — 加进 `Promise.allSettled`
- `src/vite-env.d.ts` — 类型

**踩过的坑（都是真机脚本逼出来的，务必记住）**
1. `lx.request` 不解析 JSON → 脚本读 `resp.body.code` 得 undefined，误报「脚本没有发送 inited 事件」。LX 是 `try { resp.body = JSON.parse(body) } catch {}`，必须对齐。
2. `inited` 是**异步**发送的（真实脚本要先去 registry 拉自己的源列表）→ 不能同步判定失败，改成等 `ready`（上限 8s，`unref` 定时器）。
3. 沙箱 `console` 必须补 `group/groupEnd/table/trace/dir/count/time`：多个脚本第一行日志就 `console.group`，缺了直接死。
4. `lx.utils.crypto` 要 `aesEncrypt(buffer, mode, key, iv)` 和 `rsaEncrypt(buffer, key)`（RSA_NO_PADDING + 前导 0 补到 128 字节）；`lx.utils.zlib.inflate/deflate` 返回 Promise。
5. 脚本在 `lx.request` 回调里抛错会变成**主进程未捕获异常**（测试进程直接崩）→ `http.cjs` 的 `finish` 必须 try/catch。
6. 单脚本失败要自动换下一个（公益源死亡率极高），但必须加**总预算 25s**、单脚本 12s，否则装十几个脚本时播放键要转几分钟。
7. `describeError` 不能用 `instanceof Error`：vm 跨 realm 拿不到本 realm 的 Error 原型，`JSON.stringify` 还会给出 `{}`。要按 shape 读 `message`/`stack`。

**实测（23 个公开脚本，2026-10-28）**：22/23 能发出 `inited`；`kw` 真取到可播放 mp3（monster.js）；`wy`/`tx` 失败全是脚本背后服务器已死（404 / ENOTFOUND / 超时）。野花v1.js 能加载、能给五个源，但它的 `97.64.37.235` 返回 404 —— 服务下线，不是宿主问题。唯一初始化失败：六音 v1.0.7（脚本自身在 vm 里跑不起来）。

**环境事实**：`package.json` 的 `name=folia-major`、`productName=Folia` → userData 是 `%APPDATA%\Folia`。仓库无 `node_modules`，从没跑过，所以用户看不到 `custom-sources` 目录。已代建 `%APPDATA%\Folia\custom-sources` 并放入 `野花v1.js`。用户需自行 `npm install` + `npm run dev:electron`（构建/运行由用户操作）。

**收尾又修的两个坑**
- `package.json` 的 electron-builder `files` 白名单缺 `custom-source/**/*` → 开发能跑、打包后 `require` 崩。已加。
- `src/bootstrap.tsx` 原先把 `installCustomSourceExtension()` 放进 `Promise.allSettled` 一起等，而它首次要等脚本 `inited`（最长 8s）才 resolve，`renderApp()` 在其后 → 一个坏脚本白屏 8s。已改成独立 fire-and-forget（provider 在模块加载时已注册，晚包一层不影响播放）。
- `tsc --noEmit` 退出码 0，无类型错误。

**扩展接入点的取舍（重要）**：`src/services/hostExtensionHooks.ts` 有现成的 `installOmniResultHooks({ audio })`，看似更合适，但它是**单槽位**且已被 `src/mods/folium/experimental.ts:103` 占用，接了会把 Folium mod 的钩子顶掉。所以走注册表包装（`registerOnlineMusicProvider` 一个 spread 副本、只换 `playback.getAudioSource`），不动共享基础设施。

**还没做**：插件管理界面（列表/开关/从 URL 装/从文件装/显示错误）、给媒体地址按域名补 `Referer`（部分源必需）、`updateAlert` 版本提示、`local` 源、列表导入导出、移动端。

## 内置音源（builtin provider）+ .lxmc 歌单导入

**新需求**：① 歌单不该只有登录才有，要能导入，PC + 手机都要，主页显示；② 搜索是手机端硬需求。

**落雪怎么搜索（读了 lyswhut/lx-music-desktop 源码）**：搜索是**播放器内置**的，不在自定义音源协议里。`src/renderer/utils/musicSdk/{wy,tx,kg,kw,mg,bd}/` 各有一套 `musicSearch.js` / `songList.js` / `musicDetail.js` / `lyric.js`，网络层 `httpFetch` 在原生侧 → 无 CORS。手机版共用同一套，所以手机能搜。网易云新版用 eapi 签名（`eapiRequest('/api/search/song/list/page', {keyword, needCorrect, channel, offset, scene, total, limit})`），**注释里那条旧路径 `/api/cloudsearch/pc` 实测仍然免加密可用**，省掉复刻 eapi。

**实测可用的直连接口（2026-10-28）**：
- 网易云搜索 `POST https://music.163.com/api/cloudsearch/pc`（form: s/type=1/limit/offset/total/csrf_token）→ `result.songs[]`，字段 `{id, name, ar:[{id,name}], al:{id,name,picUrl}, dt(ms), fee}`。**注意 `al` 是对象不是数组**（踩过：当成数组导致专辑/封面全空）。
- QQ 搜索 `GET https://c.y.qq.com/soso/fcgi-bin/client_search_cp?w=&format=json&n=&p=&cr=1&new_json=1` → `data.song.list[]`，字段 `{mid, name, interval(秒!), singer:[{name}], album:{mid,name}, file:{media_mid}}`；封面 `https://y.gtimg.cn/music/photo_new/T002R500x500M000{album.mid}.jpg`。
- 网易云歌词 `GET music.163.com/api/song/lyric?id=&lv=-1&kv=-1&tv=-1` → `{lrc, tlyric, nolyric}`。
- QQ 歌词 `GET c.y.qq.com/lyric/fcgi-bin/fcg_query_lyric_new.fcg?songmid=&g_tk=5381&format=json&nobase64=1`（需 Referer y.qq.com）。
- 酷狗 `mobilecdn.kugou.com` / `msearchcdn.kugou.com` **本机 HTTP 000 连不通**，未接。

**`.lxmc` 结构（反直觉，必须记住）**：gzip 压缩的 JSON（magic `1f 8b`），`{type:"playList_v2", data: [...]}` —— **data 是数组**（keys 显示 '0'..'5' 容易被当成对象，务必用 `Array.isArray` 判断，否则整包会被误判成"单个歌单"）。单歌单导出是 `{type:"playListPart", data:{id,name,list}}`。判断依据应该是「data 自己有没有 `list` 数组」，不是"是不是对象"。
Song：`{id:"wy_417250673", name, singer, source, interval:"03:48", meta:{songId, albumName, albumId, picUrl, qualitys:[{type:"320k", hash}]}}`。酷狗每个音质一个 hash，取 320k 那条。

**实现**（`src/extensions/builtin/`）：`model.ts`（id 编解码 `平台:nativeId`、歌曲转换、toLxMusicInfo）、`lxmc.ts`（解析）、`store.ts`（IndexedDB cache key `builtin_imported_playlists` + 订阅）、`search.ts`、`lyrics.ts`（用项目现成 `parseLyricsByFormat('lrc', ...)`）、`provider.ts`（注册 `builtin` provider）、`useImportedPlaylists.ts`（`useSyncExternalStore`）。

**关键设计**：
- 歌的 `sourceRef = {kind:'online', providerId:'builtin', mediaId:'wy:417250673'}`，平台信息编进 mediaId → 一个 provider 能服务混源歌单（那份 389 首的「本地」里混了 wy/tx/kg/kw）。
- `builtin.playback.getAudioSource` 自己调 `getCustomSourceBridge().resolveUrl`（不走 customSource 那层 provider 包装，因为 id 不是 netease/kugou/qq）。
- 主页显示：不走 account.collections（那是登录才有），改在 `buildHomeModel.ts` 的 `playlists` 前面拼 `importedPlaylists`，由 `useHomeModel` 用 `useImportedCollections()` 注入。
- 手机端默认源：`useOnlineProviderAccountStore.getInitialProviderId()` 在无 stored 值且 `window.Capacitor.isNativePlatform()` 时返回 `builtin`。
- `OnlineProviderId = 'netease' | (string & {})` → 任意 id 可注册（这是整个方案的前提）。`id` 放行因为 `providerRegistry` 是 Map。
- 设置导航 `electronOnly` 之外新增 `requiresScriptHost`（设置 → 高级 → 自定义音源 在手机可见）。

**踩过/易错**：`Line.startTime` 单位是**秒**（`parseTimestamp` 返回 `min*60+sec+fraction`），不是毫秒 —— probe 里标 ms 会看成 bug。`parseLyricsByFormat` 签名是 `(format, content, translation, options, romanization)`。

**验证**：`npx tsx test/manual/builtin_import_probe.ts "D:/驱逐舰/lx_list.lxmc"` → 6 歌单 / 709 首，封面 + kgHash + qqMid 齐全；`npx tsx test/manual/builtin_search_probe.ts 月半小夜曲 [--qq]` → 网易云 300 条、QQ 1001 条、歌词 42 行。`tsc --noEmit` 0 错，`vite build` 通过，产物已 robocopy 同步到 android assets（1905 文件）。

**未在真机/运行时验证**：provider 切换器是否列出「内置音源」、搜索 tab 是否带上它、播放链路（resolveUrl 真出地址）、主页卡片点击能否进集合页。这些要用户 `npm run dev:electron` 或装 APK 才能看。

### 修「导入歌单好像不支持落雪的」（同日补）

**根因不是解析器**（4 个真实 `.lxmc` 全部解析正常：6/6/1/1 个歌单）。是三处产品逻辑把它挡在门外：

1. **首页「导入歌单」的文件框 `accept` 只有 `.m3u,.m3u8`** → `.lxmc` 在选择框里根本选不中。三套 surface 各写死一份（`LocalGrid3DView` / `LibraryTuiHomeLists` / `BravaisHomeSources`），已抽成 `src/library/core/home/playlistFileAccept.ts` 的 `PLAYLIST_FILE_ACCEPT`。
2. **本地歌单导入只认 m3u**（`localPlaylistFileService` 按路径匹配本地歌曲，喂 `.lxmc` 只会得到「没有路径能匹配」）。改为在宿主端口 `createLibraryHomePort.importPlaylistFile` 里先嗅探内容：`looksLikeLxPlaylist(bytes)`（gzip 头 `1f 8b` 或 `type: playList*` 的 JSON）→ 转给内置音源；否则走原来的 m3u 匹配。结果里加 `handled: true`，`libraryHomeActions.service` 见到它就提前返回，不报「没有匹配」。
3. **主页在线歌单被账户门槛盖住**：`resolveHomeOnlineSource` 写的是 `collections: provider?.collections || fallback`，一旦平台摘要到位（含未登录的空数组）导入的歌单就没了；且 `canUsePlaylists = userLibrary && playlists`，内置源 `userLibrary: false` → 「歌单」页签判为不可用；`accountless`/`guest` 面板在 TUI 与 Grid3D 里直接顶掉列表。三处都改成「有自己的歌单时就显示」。

**改动清单**：`extensions/builtin/lxmc.ts`（新增 `looksLikeLxPlaylist`）、`extensions/builtin/index.ts`（`readPlaylistBytes`、`NOT_LX_PLAYLIST` 文案）、`extensions/builtin/provider.ts`（`userLibrary: true`，只为让歌单页签可用，不引入登录）、`library/core/home/homeSources.ts`（平台列表与自有列表分开拼）、`library/app/createLibraryHomePort.ts`（嗅探分流 + 卡片沿用 `collection.providerId`）、`libraryHomeActions.service.ts`、`homeModel.contract.ts`（`handled?`）、`LibraryTuiHomeLists.tsx` / `Grid3D.tsx`（`hasOwnLists` 放行）、`settingsNavModel.ts`（自定义音源页不再 `requiresScriptHost`，浏览器里也能导入歌单）、4 个语言文件的 `playlistImportLx` / `playlistImportEmpty`。

**教训（下次直接照做）**：导入类功能先看**入口的 accept 和 gate**，再看解析器。另外「provider 摘要一到位就覆盖 fallback 列表」这种写法，天然会把不挂账户的自有数据吞掉。
